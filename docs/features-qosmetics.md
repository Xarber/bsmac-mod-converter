# Automatic Qosmetics notes

Place `.cyoob` packages in the game's `CustomNotes` directory. The existing equipment worker picks them up on startup or through file notifications. Once preparation finishes, use **Reload** in CustomNotes to see the new model. `rescan-equipment` also discovers `.cyoob` files. The original archive stays in place. The generated `.bloq` and its metadata live under `CustomNotes/Qosmetics`. The loader verifies the generated file's SHA-256 and asks Unity to enforce its CRC before adapting the prefab.

The reader uses `package.json` to locate the PC UnityFS bundle, verifies the standard Qosmetics note prefab, and selects existing Metal or runs strict shader conversion as necessary. Android-only bundles, malformed archives and unrecognized layouts fail with diagnostics. The original bundle preserves its meshes, materials, textures and animation data. Package name, author, description and arrow preference set the desktop note descriptor. Bombs, dots and chain parts are optional. Missing optional parts use CustomNotes' existing behavior.

The verified Plasma-specific path and material property block logic from the user's handoff were retained. Prepared packages reuse the material color adapter for arrows, dots and chains. Color goes to each authored `_CustomColors` slot, preserving alpha and static materials. The existing installed Plasma Notes stays on its original path. Debris is present in some source bundles but CustomNotes does not consume the Qosmetics debris hierarchy through this adapter. External avatars, packaged walls and sabers, Android-only shader translation, and visual verification of generalized prefabs remain open.

Rehearsal converted the local Plasma Notes and True Acc Bloq V2 packages, checked persisted output and native Metal compilation, then reused both on a second rescan. The latter is staged in the live game for the first runtime test. Keep model archives, extracted bundles, and game or plugin assemblies outside Git.
